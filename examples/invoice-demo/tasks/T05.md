# T05: Review summary a human can approve at a glance

Acceptance (owner: Marketing): Marketing's examples in `acceptance/marketing/EXAMPLES.md` (section T05) and the
protected tests in `acceptance/marketing/t05.test.mjs` (tests `T05 …`). Do not change them.

Add `Invoice.prototype.reviewSummary(threshold = "50000.00")` returning a plain object with **exactly** these keys:
`lines` (integer, number of lines), `net`, `vat`, `gross` (`Decimal`, equal to `netTotal()`,
`vatTotal()`, `grossTotal()`), `flags` (array of `{ code: string, reason: string }`),
`recommendation` (`"approve"` or `"review"`) and `reason` (string).

Flags, each with a plain-language `reason` that names what is wrong:
- `empty`: the invoice has no lines.
  Every flag's `reason` is non-empty.
- `duplicate_line`: two or more lines have the same `sku`, `unit_price`, `quantity` and `vat_class`
  (a matching SKU with a different price, quantity or VAT class is not a duplicate);
  the reason names the SKU.
- `over_threshold`: `gross` is strictly greater than `threshold` (string or `Decimal`; JS numbers
  rejected with `TypeError`, like `toMoney`); the reason states the
  effective threshold as a plain number with two decimals and no thousands separator (e.g. `50000.00`).

`recommendation` is `"approve"` if and only if `flags` is empty, otherwise `"review"`. `reason` is one
sentence: a single line, ending with `.`, at most 200 characters (code points); when reviewing it contains every
flag's code. Do not change existing behaviour. Add tests.
